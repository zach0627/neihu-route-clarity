# 有效分鐘實測車流排名

更新日期：2026-10-23，臺北時間。

使用者已確認使用目前取得的有效資料排名。主指標為：

> 有效分鐘平均車流率（輛／分鐘）＝通過品質檢查的實測累計車次 ÷ 有效分鐘總數。

這個指標直接整理觀測值，沒有推算缺漏時段的車流。它回答「目前有效觀測到的分鐘中，哪些候選路段方向平均通過較多車輛」，不能回答未被觀測的分鐘實際有多少車，也不能保證排序等於完整月份 07:00–09:30 總車流的排序。

## 資料從哪裡來

來源皆為 TDX 臺北市歷史 API：

| API | 用途 |
|---|---|
| `https://tdx.transportdata.tw/api/historical/v2/Historical/Road/Traffic/VD/City/Taipei` | 以同日設備資料取得 VDID、LinkID、道路、位置、方向、車道數及行政區 |
| `https://tdx.transportdata.tw/api/historical/v2/Historical/Road/Traffic/Live/VD/City/Taipei` | 取得同日各測點的 DataCollectTime、Status、車道、車種、Volume 與品質旗標 |

本機下載腳本以 `Dates` 指定日期，使用 JSONL 取得完整資料並保存來源網址、下載時間與雜湊。只有本機 Node 腳本讀取 `.env.local` 中的憑證；React 及 build 成品讀取公開的整理快照。開啟 `dist/index.html` 不會呼叫這些 API，也不會攜帶憑證。

## 如何計算一個名次

1. 日期為最近 30 個完整日曆日內的週一至週五；排除週六日，尚未扣除國定假日。固定使用臺北時間。
2. 將每筆 `DataCollectTime` 轉為臺北時間，保留 `07:00 ≤ 時標 < 09:30`，每天預期 150 個分鐘標記。時間標記是統計區間起點或終點仍待官方確認，實際時段邊界可能差一分鐘。
3. 用同日靜態資料選出內湖區測點，只保留「入園路段」與「園區內路段」：依臺北市商業處的園區門牌範圍與 TDX 官方路段幾何判定（見 [方向範圍說明](directional-scope.md)）。同一 LinkID 僅採一支固定優先序的代表測點。沒有依流量或資料完整度挑選較有利的測點。
4. 分析單位是「VDID × LinkID × 臺北日期 × 分鐘」。每個方向分鐘內，加總所有車道、各車種的原始 `Volume`。
5. 沿用既有保守品質規則：`Status=0`；車道數與同日靜態 `LaneNum` 一致；若有 `ActualLaneNum` 也須一致；車道與車種無重複；`Volume` 是非負整數；所有車道 `ErrorDiags` 只有 `diag0`。完全相同的重複分鐘只計一次，內容衝突的分鐘排除。未通過表示不符合本專案篩選，並非已證明原始 Volume 一定錯誤。
6. 對每一代表方向，將所有有效分鐘的車次加總，除以有效分鐘總數。有至少一個有效分鐘即可參與排名，不另設 80%、90% 等完整度門檻；以未四捨五入的車流率降序比較，最多顯示十名。
7. 同時呈現實測累計、有效分鐘、完整度、逐日紀錄與排除原因。不將平均值乘上 150，不把不合格分鐘或缺漏分鐘補成零，也不以其他時刻代替。

若一天 100 個有效分鐘合計 2,000 輛，另一天 50 個有效分鐘合計 500 輛，整期平均為 `(2,000 + 500) ÷ (100 + 50) = 16.67 輛／分鐘`。這是按分鐘加權，不是兩天平均值 20 與 10 的等權平均 15。兩天未觀測的車流不在計算內。

## 選擇這個口徑的影響

各方向有效分鐘不同，也可能來自不同日期、不同早上時刻。用有效分鐘除法使觀測時間長短能夠比較，但不會自動消除取樣偏差：若某路段偏偏在最忙的時刻缺測，算出的平均可能較低；若較安靜時段較常被品質規則排除，平均可能較高。因此排名須和完整度及逐日紀錄一起閱讀。完整度低的第十名仍保留其實際名次與數字，沒有把缺漏當成車流不存在。

「所有所選日期都完整 150 分鐘」的嚴格指標繼續保留作診斷，目前合格方向為 0。這和有效分鐘車流率有不同的問題定義；主排名不再因為某一天少一個分鐘就把整個方向排除。舊版空排名的具體原因見 [排名診斷](ranking-diagnostics.md)。

往園區路段由官方門牌範圍與官方路段幾何判定，不是車輛目的地調查；VD 無法識別車輛最終目的地。結果是有偵測器涵蓋的往園區路段觀測排名，並非所有實際進入園區的車流總數，也不是壅塞程度排名；壅塞排名另見 [塞車計算方式](congestion-method.md)。

## 重現與更新

```sh
npm run data:aggregate -- --start 2026-09-23 --end 2026-10-22
npm run build
```

第一步從本機已下載快取重新計算公開快照；第二步將快照封裝到單檔 `dist/index.html`。更新資料之後必須重新 build 並開啟新產出的檔案。來源追溯、真實分鐘加總範例與品質規則也呈現在網站的「資料來源與計算」頁。
